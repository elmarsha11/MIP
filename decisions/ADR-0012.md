ADR-0012: Se admite http:// cuando el municipio no tiene HTTPS

Fecha: 2026-08-07
Estado: Aceptado
Relacionado: ADR-0009, ADR-0011, schemas/discovery_schema.md (regla "URL debe ser absoluta con https://")

## Contexto

`schemas/discovery_schema.md` exige que toda URL sea absoluta y empiece con
`https://`. Al ampliar la cobertura de Fase 3 con las pistas de Wikidata
aparecieron municipios cuyo sitio oficial **solo existe sin TLS**:

- Rauch: `http://www.rauch.mun.gba.gov.ar/web/` responde 200 con titulo
  "Municipalidad de Rauch". En `https://` no responde nada.
- Villarino: `http://www.villarino.gob.ar/` responde 200 con titulo
  "Municipio de Villarino". En `https://` no responde nada.

Con la regla anterior estos dos municipios quedaban como "sin sitio oficial",
que es falso: el sitio existe y esta funcionando.

Peor: el codigo convertia `http://` a `https://` antes de consultar, lo que
transformaba una URL viva en una URL muerta. Se estaba fabricando una ausencia.

## Decision

1. `DiscoveryURL.url` exige **URL absoluta**, admitiendo `https://` y `http://`.
   Se elimina toda conversion automatica de esquema.
2. Al descubrir el dominio se prueba **https primero y http despues**, en dos
   tandas. La segunda tanda solo corre si la primera no acredita nada, asi que
   los ~75 municipios con TLS no pagan pedidos de mas.
3. La deduplicacion ignora el esquema: `http://x/transparencia` y
   `https://x/transparencia` son la misma pagina. Se guarda una sola y, a
   igualdad de todo lo demas, gana la version https.
4. Se agrega la columna `sitio_sin_https` a `municipios_discovery`:
   1 = el sitio oficial no ofrece TLS, 0 = lo ofrece, NULL = no se encontro sitio.

## Fundamento

La intencion de la regla original es "URL absoluta, no relativa". No fue una
decision de excluir municipios sin TLS: es un caso que no se habia visto todavia.

Y hay algo mas importante. MIP existe para medir madurez digital municipal.
**Que un municipio no ofrezca HTTPS en 2026 no es un obstaculo para el
relevamiento: es uno de los datos que el relevamiento tiene que capturar.** Un
portal sin TLS no puede tener pagos online seguros ni turnos con datos de salud.
Es una senal directa de nivel Basico segun el diccionario de datos.

Descartar esos municipios por no cumplir un formato hubiera sido, justamente,
ocultar un vacio: exactamente lo que prohibe ADR-0009.

## Consecuencias

Positivas:

- Rauch, Villarino y Tordillo se recuperan con confianza Alta.
- Aparece una variable nueva y vendible para Fase 5: que municipios no tienen TLS.
- Se elimina un bug que mataba URLs vivas.

Negativas:

- Se relaja una regla del schema. Queda registrado aca y en el validador.
- Al leer paginas http no hay garantia de integridad del contenido. Para Fase 4
  (scraping con 5 sellos) hay que dejar constancia de que el fragmento se
  obtuvo por un canal sin cifrar.

## Verificacion

- `test_admite_http_para_municipios_sin_tls`: acepta el caso Villarino.
